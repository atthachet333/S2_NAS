# มุมมองอัจฉริยะ

## ไม่ใช่โฟลเดอร์

มุมมองอัจฉริยะคือ **ชุดเงื่อนไขสำเร็จรูป** ไม่ใช่ที่เก็บ

- ไม่มีการคัดลอกหรือย้ายทรัพยากร
- เอกสารหนึ่งฉบับอยู่ในหลายมุมมองพร้อมกันได้
- เอกสารหายไปจากมุมมองเองเมื่อสถานะของมันเปลี่ยน โดยไม่ต้องมีใครมาจัดระเบียบ

## มุมมองที่มีมาให้

| มุมมอง | คัดอะไร |
|---|---|
| ต้องตรวจ OCR | อ่านด้วย OCR สำเร็จแล้ว แต่ยังไม่มีคนตรวจ |
| OCR ล้มเหลว | สั่งอ่านแล้วไม่สำเร็จ ต้องมีคนเข้าไปจัดการ |
| ตรวจแก้แล้ว | มีคนอ่านด้วยตาแล้วยืนยันหรือแก้ |
| ลูกค้าอัปโหลด | `sourceType = EXTERNAL_UPLOAD` |
| ไฟล์ล่าสุด | อัปโหลดใน 7 วันที่ผ่านมา |
| ไฟล์ขนาดใหญ่ | เรียงตามขนาด ใช้ตรวจก่อนพื้นที่เต็ม |
| เอกสารที่ไม่มี Tag | ยังไม่ถูกจัดระเบียบ |
| ยังไม่ระบุประเภทเอกสาร | ยังไม่ได้กำหนดประเภท |
| เอกสารที่ฉันดูแล | `ownerId` = ผู้เรียก |

จงใจให้มีจำนวนน้อยและทุกอันตอบคำถามที่คนถามจริงในการทำงานประจำวัน
การใส่มุมมองสำเร็จรูปมาสามสิบอันจะทำให้ไม่มีใครใช้อันไหนเลย

## "เอกสารที่ฉันดูแล" ≠ "เอกสารที่ฉันอัปโหลด"

ใช้ **ผู้ดูแล** (`ownerId`) ไม่ใช่ **ผู้สร้าง** (`createdById`)

สองอย่างนี้มักไม่ใช่คนเดียวกัน - ธุรการอัปโหลดเอกสารให้ฝ่ายบัญชี คนที่ต้องรับผิดชอบ
คือฝ่ายบัญชี ไม่ใช่ธุรการที่กดอัปโหลด

รหัสของผู้เรียกถูกผูกเข้าไปตอนเรียกใช้ ไม่ได้ฝังไว้ในค่าคงที่ - ค่าคงที่ถูกสร้าง
ครั้งเดียวตอนโหลดโมดูล ส่วนผู้เรียกเปลี่ยนไปทุกคำขอ

## "ต้องตรวจ OCR" ไม่รวมเอกสารที่มีข้อความอยู่แล้ว

กรอง `textSource = OCR` เท่านั้น เอกสารที่มีข้อความฝังอยู่ในไฟล์จริง (`NATIVE_TEXT`)
ไม่ได้ผ่านการเดาของเครื่อง จึงไม่มีอะไรให้ตรวจ

## ไม่ใช่ทางลัดข้ามสิทธิ์

ทุกมุมมองเดินผ่าน `searchResources()` ตัวเดียวกับการค้นหาปกติ จึงผ่านด่านสิทธิ์
ชุดเดียวกันทั้งหมด มุมมองอัจฉริยะไม่มีสิทธิ์พิเศษใด ๆ และไม่ใช่เครื่องมือของผู้ดูแล

## เส้นทาง

```
GET /api/smart-views          รายชื่อมุมมอง
GET /api/smart-views/:slug    ผลลัพธ์ของมุมมองหนึ่ง
```

หน้าจอ: `/smart-views/:slug`
