# นโยบายการเก็บรักษาเอกสาร

> **ข้อความสำคัญ**
>
> ระยะเวลาการเก็บรักษาที่ระบบมีมาให้เป็นเพียง **ตัวอย่างที่แก้ไขได้**
> **ไม่ใช่คำแนะนำทางกฎหมาย** และ **ไม่รับประกันว่าสอดคล้องกับกฎหมายไทย**
>
> องค์กรต้องกำหนดระยะเวลาเองตามที่ปรึกษาทางกฎหมายหรือบัญชีของตน
> ระบบทำหน้าที่ *บังคับใช้* สิ่งที่องค์กรกำหนด ไม่ใช่ *ตัดสิน* ว่าควรกำหนดอะไร

## ไม่ใช่เรื่องเดียวกับอายุของชุดสำรอง

นี่คือความสับสนที่เกิดง่ายที่สุดและมีราคาแพงที่สุด

| | อายุชุดสำรอง (F6) | นโยบายการเก็บรักษา (F16) |
|---|---|---|
| ตอบคำถาม | เก็บ *ไฟล์สำรองของทั้งระบบ* ไว้กี่ชุด | ห้ามลบ *เอกสารฉบับนี้* จนกว่าจะถึงเมื่อไร |
| ตั้งค่าที่ | หน้า Backup | หน้าการเก็บรักษา |
| กระทบอะไร | พื้นที่ดิสก์ของชุดสำรอง | สิทธิ์ในการลบเอกสาร |

การลดอายุชุดสำรองไม่ทำให้เอกสารถูกลบ และการหมดอายุการเก็บรักษาไม่ทำให้ชุดสำรองหาย

## แบบจำลอง

```
RetentionPolicy
  name · description · retentionDays | retainForever · isActive · sortOrder
```

ต้องระบุ **อย่างใดอย่างหนึ่ง**: จำนวนวัน หรือเก็บถาวร นโยบายที่ไม่ระบุทั้งสองอย่าง
จะไม่คุ้มครองอะไรเลย แต่หน้าจอจะแสดงว่ามีนโยบายอยู่ ซึ่งหลอกผู้ใช้ - ระบบจึงปฏิเสธ

## วันเริ่มนับ

| ค่า | ความหมาย |
|---|---|
| `CREATED_AT` | วันที่นำเข้าระบบ (ค่าเริ่มต้น) |
| `MANUAL` | วันที่เจ้าหน้าที่ระบุเอง เช่น วันที่บนเอกสารจริง |

**ไม่มีตัวเลือก "เดาวันที่จากเนื้อในเอกสาร" โดยตั้งใจ**

OCR อ่านวันที่ผิดได้ และการเดาผิดจะทำให้เอกสารถูกลบก่อนกำหนดโดยไม่มีใครรู้ตัว
ถ้าต้องใช้วันที่บนเอกสารจริง ให้คนพิมพ์เข้าไปเอง ซึ่งบันทึกไว้เป็น `MANUAL`

## วันหมดอายุเป็นภาพนิ่ง

เมื่อกำหนดนโยบายให้เอกสาร ระบบคำนวณ `retentionUntil` **ครั้งเดียว** แล้วเก็บไว้

การแก้นิยามของนโยบายภายหลัง **ไม่เปลี่ยน** วันหมดอายุของเอกสารที่กำหนดไว้แล้ว

เหตุผล: ถ้าคำนวณใหม่ทุกครั้งที่อ่าน การแก้ตัวเลขเดียวจะเปลี่ยนวันหมดอายุของเอกสาร
หลายพันฉบับพร้อมกัน และบางฉบับจะกลายเป็น "ลบได้แล้ว" ทั้งที่เมื่อวานยังห้ามลบ
ซึ่งเป็นผลข้างเคียงที่มองไม่เห็นจนกว่าจะมีคนลบไปแล้ว

ต้องการให้มีผลย้อนหลังจริง ๆ ให้กด **คำนวณใหม่** ในหน้าผู้ดูแล ซึ่งบอกจำนวนเอกสาร
ที่จะกระทบก่อนยืนยัน

## เก็บถาวร

`retainForever = true` → `retentionUntil = null`

แยกจาก "ไม่มีนโยบาย" ด้วยฟิลด์ `retentionForever` บนทรัพยากร ทั้งสองกรณีมี
`retentionUntil = null` เหมือนกัน แต่ความหมายตรงข้ามกันโดยสิ้นเชิง

## นโยบายเริ่มต้นของประเภทเอกสาร

`DocumentCategory.defaultRetentionPolicyId` ใช้เมื่อจัดเอกสารเข้าประเภท

**ใช้เฉพาะกับเอกสารที่ยังไม่มีนโยบายของตัวเอง** ไม่เขียนทับสิ่งที่คนตั้งใจกำหนดไว้
การเปลี่ยนประเภทเอกสารไม่ควรมีผลข้างเคียงเป็นการลดการคุ้มครองที่มีอยู่

## สิทธิ์

| การกระทำ | ต้องมี |
|---|---|
| ดูรายการนโยบาย | ผู้ใช้ภายในทุกคน |
| กำหนดนโยบายให้เอกสาร | สิทธิ์แก้ไขเอกสารนั้น |
| สร้าง / แก้ / ปิด / ลบนโยบาย | `system:retention:manage` (SUPER_ADMIN, ADMIN) |
| คำนวณใหม่ย้อนหลัง | `system:retention:manage` |

การ *กำหนด* นโยบายให้เอกสารเป็นการจัดการเอกสาร ส่วนการ *นิยาม* นโยบายเป็นการตั้งค่าระบบ
สองอย่างนี้จึงใช้สิทธิ์คนละระดับ

สิทธิ์ถูกเพิ่มผ่าน `npm run rbac:sync` ซึ่งแตะเฉพาะตาราง Permission/Role/RolePermission
ไม่แตะบัญชีผู้ใช้หรือรหัสผ่านใด ๆ

## หมดอายุแล้วไม่ได้แปลว่าถูกลบ

**ระบบไม่เคยลบเอกสารเองเพียงเพราะนโยบายหมดอายุ**

หมดอายุแปลว่า "ลบถาวรได้แล้วถ้ากติกาอื่นอนุญาต" - เอกสารยังต้องถูกย้ายลงถังขยะ
และยังต้องมีคนมีสิทธิ์กดลบ มุมมอง **หมดอายุการเก็บรักษา** มีไว้ให้ผู้ดูแลเห็นว่า
มีอะไรพร้อมให้พิจารณาบ้าง ไม่ใช่คิวการลบอัตโนมัติ
