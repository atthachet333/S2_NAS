# F24 final report — PWA / Mobile Experience

วันที่ตรวจ: 16 กันยายน 2026
Baseline: `f5c7f3f` (F23 object storage)
Release state: **implemented, uncommitted, ไม่มีการเปลี่ยนแปลงฝั่งหลังบ้านหรือฐานข้อมูลเลย**

> **สิ่งที่ต้องอ่านก่อน:** service worker **ยังไม่เคยลงทะเบียนสำเร็จในสภาพแวดล้อมที่มีอยู่**
> เบราว์เซอร์ที่ฝังอยู่ในเครื่องมือปฏิเสธสคริปต์ของ service worker แม้จะเสิร์ฟจาก
> production build บนบริบทที่ปลอดภัยและมี MIME ถูกต้อง และส่วนขยาย Chrome ตัวจริง
> ต่อไม่ติดตลอดช่วงงานนี้ ความปลอดภัยของ Cache Storage ขณะมี service worker ทำงานจริง
> จึงยังเป็นช่องว่างที่ยอมรับไว้ ไม่ใช่สิ่งที่ผ่านการตรวจ รายละเอียดอยู่ในหัวข้อ 12

## 1. สิ่งที่ F24 เปลี่ยน

1. **แอปเดียวกันทั้งมือถือและเดสก์ท็อป** ไม่มีโค้ดเบสแยก และ PWA เป็นส่วนเสริมเสมอ
   ถ้า service worker ลงทะเบียนไม่ได้ แอปทำงานเหมือนเว็บไซต์ปกติทุกประการ
2. **จุดตัดสองจุด ไม่ใช่จุดเดียว** `< 768px` คือโทรศัพท์ (แถบล่าง แผ่นกระทำ)
   ส่วน `< 1024px` คือ "ตารางอ่านไม่ออก" (ใช้การ์ดแทน) สองคำถามนี้ไม่ใช่คำถามเดียวกัน
3. **ไม่มีการแคชคำตอบของ API เลยแม้แต่แบบเดียว** เพราะโทเค็นอยู่ใน header ไม่ใช่คุกกี้
   คำขอของผู้ใช้คนละคนจึงมีคีย์แคชเดียวกัน
4. **ไม่มีคิวการเขียนเบื้องหลัง** ทั้งการอัปโหลด การย้าย และคำถามถึงผู้ช่วย
   ออฟไลน์แล้วถูกปฏิเสธทันที ไม่ถูกเก็บไว้ส่งให้เองภายหลัง

## 2. ข้อบกพร่องที่พบและแก้ระหว่าง F24

พบจากการทดสอบจริงทั้งหมด ไม่ใช่จากการเดา:

5. **ปุ่มค้นหาบนมือถือไม่มีตัวจัดการเหตุการณ์เลย** กดแล้วไม่มีอะไรเกิดขึ้นมาตั้งแต่ต้น
6. **ปุ่มตัวเลือกของทุกแถวถูกซ่อนด้วย `opacity-0` จนกว่าเมาส์จะชี้** บนจอสัมผัสจึงไม่มีทาง
   เปิดเมนูของไฟล์ได้เลย แก้ทั้ง 6 จุด และมีชุดทดสอบสแกนซอร์สกันไม่ให้กลับมา
7. **ตารางกว้าง 1040px บนจอ 375px** ผู้ใช้ต้องเลื่อนแนวนอนเพื่อดูข้อมูลของไฟล์
8. **การกดอ้างอิงในผู้ช่วยเอกสารทำลายบทสนทนา** เดิมปิดแผงทิ้งแล้วล้างข้อความทั้งหมด
   ตอนนี้ย่อไว้และกลับเข้าบทสนทนาเดิมได้
9. **ปุ่มบนแถบหัวเรื่องของหน้าตัวอย่างไฟล์ไม่มีชื่อ** ป้ายถูกซ่อนด้วย `hidden sm:inline`
   โดยไม่มี `aria-label` สำรอง ตัวอ่านหน้าจอบนมือถือจึงอ่านไม่ออกว่าปุ่มไหนคืออะไร
10. **ตัวจับเหตุการณ์ติดตั้งแอปถูกติดตั้งช้าเกินไป** `beforeinstallprompt` ยิงครั้งเดียวและยิงเร็ว
    แต่เดิมตัวรับอยู่ในคอมโพเนนต์ที่ถูกสร้างเมื่อผู้ใช้เปิดเมนู ซึ่งสายเกินไปเสมอ
    ย้ายไปเป็นที่เก็บระดับโมดูลที่เริ่มทำงานพร้อมแอป
11. **คำสั่งเขียนที่ถูกปฏิเสธตอนออฟไลน์จะถูกส่งเองเมื่อเน็ตกลับมา** ค่าเริ่มต้นของ
    TanStack Query คือ `networkMode: 'online'` ซึ่งพักคำสั่งไว้แล้วเล่นซ้ำอัตโนมัติ
    แปลว่าเอกสารอาจถูกย้ายในจังหวะที่ผู้ใช้ไม่ได้สั่ง แก้เป็น `'always'` ให้ล้มเหลวทันที
12. **แถบเครื่องมือถูกตัดหายที่ขนาดตัวอักษร 200%** ปุ่มเรียง/กรอง/มุมมองล้นออกนอกพื้นที่
    และถูกซ่อนเพราะเปลือกแอปตัดการล้นแนวนอนไว้

## 3. ความสามารถเข้าถึงได้ (F24-N)

ตรวจสดบนหน้าไดร์ฟที่ 375×667 โดยเบราว์เซอร์รายงาน `pointer: coarse` จริง:

- องค์ประกอบที่กดได้ทั้งหมด **37 รายการ**
- **ไม่มีชื่อสำหรับตัวอ่านหน้าจอ: 0**
- **เล็กกว่า 40px: 0**

การขยายขนาดตัวอักษรของเบราว์เซอร์:

| ขนาด | ล้นหน้าจอ | องค์ประกอบที่ถูกตัด | แถบล่างติดขอบ |
|---|---|---|---|
| 100% | ไม่ | 0 | ใช่ |
| 125% | ไม่ | 0 | ใช่ |
| 150% | ไม่ | 0 | ใช่ |
| 200% | ไม่ | 0 | ใช่ |

แผ่นและกล่องโต้ตอบทุกตัวมี `aria-modal` ชื่อของตัวเอง ดักโฟกัส คืนโฟกัส และปิดด้วย Escape
สถานะเครือข่ายและสถานะของผู้ช่วยเป็น `role="status" aria-live="polite"`
ความมั่นใจของการจัดเก็บอัจฉริยะสื่อด้วยคำ (สูง/ปานกลาง/ต่ำ) ไม่ใช่สีอย่างเดียว

ตรวจสดบน production build ทุกความกว้าง:

| ความกว้าง | ล้นแนวนอน | การแสดงรายการ | แถบล่าง | แถบบน |
|---|---|---|---|---|
| 320×568 | ไม่ | การ์ด | ใช่ | ไม่ |
| 375×667 | ไม่ | การ์ด | ใช่ | ไม่ |
| 390×844 | ไม่ | การ์ด | ใช่ | ไม่ |

| 667×375 (แนวนอน) | ไม่ | การ์ด | ใช่ (สูง 63px) | ไม่ |
| 768×1024 | ไม่ | การ์ด | ไม่ | ใช่ |

**การตัดสินใจเรื่องแท็บเล็ตมาจากการวัด ไม่ใช่ความรู้สึก** สัดส่วนของตารางที่ต้องเลื่อน
แนวนอนไปหาด้วยชื่อไฟล์ภาษาไทยจริง: 56% ที่ 768px · 45% ที่ 1024px · 31% ที่ 1280px
ที่ 768px ผู้ใช้ต้องเลื่อนเพื่อดูข้อมูลเกินครึ่ง จุดตัดของการ์ดจึงอยู่ที่ 1024px

**ข้อจำกัดของเครื่องมือที่พบ:** การจำลองขนาดหน้าจอของเบราว์เซอร์ที่ใช้ทดสอบ
เปลี่ยนค่า `matchMedia().matches` แต่**ไม่ยิงเหตุการณ์ `change` หรือ `resize` เลย**
(วัดได้ 0 ครั้งทั้งสองอย่าง) ทุกผลในตารางนี้จึงเก็บหลังโหลดหน้าใหม่ ไม่ใช่จากการย่อขยายสด

## 6. การเก็บล่วงหน้าและฟอนต์

73 รายการ ไม่ซ้ำกัน ประกอบด้วย JS, CSS, `woff2`, ไอคอน และ `index.html` เท่านั้น
ตรวจอัตโนมัติทุกครั้งที่ build ด้วย `npm run pwa:verify` ซึ่งใช้รายการอนุญาต
ไม่ใช่รายการห้าม จึงปฏิเสธไฟล์ชนิดใหม่ที่ไม่มีใครตั้งใจให้เก็บโดยอัตโนมัติ

ฟอนต์: เก็บล่วงหน้าเฉพาะ `woff2` 15 ไฟล์ (latin, latin-ext, thai × 5 น้ำหนัก)
ไฟล์ `woff` รุ่นเก่า 20 ไฟล์และชุดอักษรเวียดนาม 5 ไฟล์ยังถูกสร้างออกมาโดย `@fontsource`
แต่ไม่ถูกส่งไปยังเครื่องผู้ใช้ **ไม่ตัดออกจากผลลัพธ์ build** เพราะต้องแก้การนำเข้าฟอนต์
ซึ่งกระทบเอกลักษณ์ของตัวอักษร - ยอมรับตามที่เป็น

## 7. ตารางความถูกต้องของการตรวจ (F24-U ข้อ 24)

### PASS — ตรวจจริงและเห็นผลจริง

| เรื่อง | หลักฐาน |

## 8. ความปลอดภัย

- โทเค็นเข้าใช้งานอยู่ในหน่วยความจำเท่านั้น · โทเค็นต่ออายุอยู่ในคุกกี้ httpOnly
  ชุดทดสอบที่สแกนซอร์สทั้งต้นไม้ยังผ่าน ไม่มีการเก็บโทเค็นลง web storage
- ไม่มีคำตอบของ API ไบต์ของเอกสาร คำตอบของผู้ช่วย หรือผลการจัดเก็บอัจฉริยะ
  อยู่ใน Cache Storage (ตรวจสดแล้วว่าง - แต่ยังไม่ได้ตรวจในสภาพที่มี SW ทำงาน)
- ไม่มี `storageKey` เส้นทางบนดิสก์ ชื่อถัง หรือคีย์ S3 ปรากฏในหน้าจอ
- ความจำเรื่องการปิดคำเชิญติดตั้งเก็บเฉพาะเวลา ไม่มีข้อมูลที่ระบุตัวผู้ใช้
