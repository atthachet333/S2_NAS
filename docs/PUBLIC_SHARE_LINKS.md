# ลิงก์แชร์ภายนอก

ส่งเอกสารให้คนที่ไม่มีบัญชี S2 NAS โดยไม่ต้องสร้างบัญชีให้เขา

```
https://nas.example.com/s/<โทเคน>
```

## ไม่ใช่พื้นที่ลูกค้า

สองอย่างนี้มีสถาปัตยกรรมแยกกันโดยตั้งใจ และต้องไม่ไหลมาปนกัน

| | พื้นที่ลูกค้า (Client Portal) | ลิงก์แชร์ภายนอก |
|---|---|---|
| ตัวตน | บัญชี EXTERNAL ที่ระบบรู้จักชื่อ | ไม่มีบัญชี มีแต่โทเคน |
| การเข้าสู่ระบบ | อีเมล + รหัสผ่าน | เปิดลิงก์ได้เลย |
| ความสัมพันธ์ | ต่อเนื่องระยะยาว | ครั้งเดียว ชั่วคราว |
| อัปโหลดได้ | ✅ | ❌ อ่านอย่างเดียว |
| ขอบเขต | ทุกอย่างที่แชร์ให้บัญชีนั้น | ทรัพยากรเดียวที่ลิงก์ระบุ |
| ยกเลิกอย่างไร | ปิดบัญชี หรือถอนสิทธิ์ | ยกเลิกลิงก์ |

**เลือกอย่างไร**: ลูกค้าประจำที่ส่งงานกันทุกเดือน ใช้พื้นที่ลูกค้า
ส่วนการส่งสัญญาหนึ่งฉบับให้คู่ค้ารายหนึ่งครั้ง ใช้ลิงก์แชร์

ดู [CLIENT_PORTAL.md](CLIENT_PORTAL.md) และ [GUEST_ACCESS.md](GUEST_ACCESS.md)

## แบบจำลอง

```
PublicShareLink
  resourceId · tokenHash · label
  createdById · createdAt · expiresAt
  allowPreview · allowDownload · passwordHash
  maxViews · viewCount · maxDownloads · downloadCount
  revokedAt · revokedById · lastAccessedAt
```

เป็นตารางของตัวเอง **ไม่ได้ใช้ `ResourceAccess` ร่วม** เพราะที่นั่นบังคับให้มี `userId`
และคีย์เอกลักษณ์คือ `(resourceId, userId)` - การยัดลิงก์แขกลงไปจะบังคับให้ต้องสร้าง
User ปลอมสำหรับแขกทุกคน ซึ่งทำให้เส้นแบ่งระหว่างพื้นที่ลูกค้ากับลิงก์แขกพังทันที

## สิทธิ์ในการสร้าง

ใช้ความสามารถ **`canShare`** ที่มีอยู่แล้ว ไม่มีระบบสิทธิ์ชุดที่สอง

| บทบาท | สร้างลิงก์ได้ |
|---|---|
| ผู้ดูแลหลักของทรัพยากร | ✅ |
| ผู้ดูแลระบบ | ✅ |
| ผู้ที่มี `resources:share` | ✅ |
| EDITOR ที่ได้รับมอบสิทธิ์ | ❌ (ตามนโยบายการแชร์เดิม) |
| VIEWER | ❌ |
| บัญชีลูกค้า / บัญชีบริการ | ❌ |

เหตุผล: "ใครควบคุมได้ว่าใครเข้าถึงเอกสารนี้" เป็นคำถามเดียวกันไม่ว่าผู้รับจะมีบัญชีหรือไม่
ถ้าแยกเป็นสองระบบ วันหนึ่งจะมีคนที่แชร์ภายในไม่ได้ แต่ปล่อยลิงก์สาธารณะได้

**สิทธิ์ยกเลิกผูกกับทรัพยากร ไม่ใช่กับผู้สร้าง** คนที่สร้างลิงก์อาจลาออกไปแล้ว
ถ้าผูกกับตัวบุคคล จะเหลือลิงก์ที่เปิดค้างโดยไม่มีใครปิดได้

## ค่าเริ่มต้นที่ปลอดภัย

| ค่า | ค่าเริ่มต้น | เหตุผล |
|---|---|---|
| ดูตัวอย่าง | เปิด | เป็นเหตุผลที่คนสร้างลิงก์ตั้งแต่แรก |
| ดาวน์โหลด | **ปิด** | ไฟล์ที่ออกไปแล้วเรียกคืนไม่ได้ ต้องเป็นการเลือกอย่างตั้งใจ |
| หมดอายุ | **7 วัน** | ลิงก์ที่ลืมปิดคือประตูที่เปิดค้างไว้ตลอดกาล |
| รหัสผ่าน | ไม่มี | เพิ่มได้เมื่อเนื้อหาต้องการ |
| เพดานการใช้ | ไม่จำกัด | ใช้เมื่อรู้แน่ว่าผู้รับจะเปิดกี่ครั้ง |

**"ไม่หมดอายุ" ไม่ใช่ตัวเลือกที่ง่ายที่สุด** ต้องเลือกจากรายการอย่างตั้งใจ
และถ้าเลือกพร้อมกับเปิดดาวน์โหลด หน้าจอจะเตือนว่าลิงก์นี้จะดาวน์โหลดไฟล์ได้ตลอดไป
- เตือน แต่ไม่ห้าม เพราะบางงานต้องการลิงก์ถาวรจริง และการห้ามจะทำให้คนไปหาวิธีอื่น
ที่ไม่มีใครมองเห็นแทน

## อายุและการยกเลิก

ตัวเลือก: 1 วัน · 7 วัน · 30 วัน · กำหนดเอง · ไม่หมดอายุ (เพดาน 730 วันสำหรับแบบกำหนดเอง)

เวลาหมดอายุเก็บเป็นเวลาสัมบูรณ์ และตรวจที่เซิร์ฟเวอร์ทุกคำขอ

**การยกเลิกมีผลทันที** ทุกคำขอ - รวมถึงคำขอเนื้อหาและดาวน์โหลด - อ่านสถานะลิงก์
จากฐานข้อมูลใหม่เสมอ ไม่มีการจำผลไว้ และใบผ่านของแขกก็ข้ามการตรวจนี้ไม่ได้

## หลายลิงก์ต่อหนึ่งเอกสาร

รองรับ และแต่ละลิงก์ยกเลิกแยกกันได้ - ใช้ได้เมื่อ:

- ลิงก์หนึ่งให้ดูอย่างเดียว อีกลิงก์ให้ดาวน์โหลด
- คนละลูกค้า คนละวันหมดอายุ
- ต้องการปิดของรายหนึ่งโดยไม่กระทบอีกราย

เพดาน **20 ลิงก์ที่ยังใช้งานได้** ต่อทรัพยากร บังคับที่เซิร์ฟเวอร์
ลิงก์ที่เปิดอยู่คือประตูที่ยังไม่ได้ล็อก ยี่สิบบานต่อเอกสารหนึ่งฉบับแปลว่า
ไม่มีใครรู้แล้วว่าใครเข้าถึงอะไรได้บ้าง

## เวอร์ชันของไฟล์

ลิงก์ชี้ที่ **เวอร์ชันปัจจุบัน** ของทรัพยากรเสมอ อัปโหลดเวอร์ชันใหม่แล้วผู้รับเห็นฉบับล่าสุด

เหตุผล: ลิงก์แชร์คือการบอกว่า "นี่คือเอกสารของเรา" ไม่ใช่ "นี่คือภาพนิ่งของวันนี้"
ถ้าแก้เอกสารแล้วผู้รับยังเห็นฉบับเก่า เขาจะทำงานผิดโดยไม่มีทางรู้

การตรึงไว้ที่เวอร์ชันหนึ่งเป็นความสามารถคนละอย่างที่ต้องเลือกอย่างตั้งใจ
จึงยังไม่มีในเฟสนี้ แทนที่จะมีทั้งสองอย่างแบบกำกวม

## ย้ายและเปลี่ยนผู้ดูแล

ลิงก์ผูกกับ **id ของทรัพยากร ไม่ใช่เส้นทาง** ผลคือ:

- ย้ายไฟล์หรือโฟลเดอร์ภายใน → ลิงก์ยังใช้ได้
- เปลี่ยนผู้ดูแลหลัก → ลิงก์ยังใช้ได้ และผู้ดูแลคนใหม่ยกเลิกได้
- แก้สิทธิ์การแชร์ภายใน → ไม่กระทบลิงก์ เพราะลิงก์เป็นการมอบสิทธิ์ของตัวมันเอง

## วงจรชีวิตของเอกสาร

| สถานะเอกสาร | สร้างลิงก์ใหม่ | ลิงก์เดิม |
|---|---|---|
| ใช้งานอยู่ | ✅ | ✅ ใช้ได้ |
| ในถังขยะ | ❌ | ❌ ปิดชั่วคราว |
| กู้คืนจากถังขยะ | ✅ | ✅ กลับมาใช้ได้ (ถ้าไม่ถูกยกเลิกและไม่หมดอายุ) |
| เก็บเข้าคลัง | ❌ | ❌ ปิดชั่วคราว |
| นำออกจากคลัง | ✅ | ✅ กลับมาใช้ได้ |
| ลบถาวร | ❌ | ❌ แถวลิงก์ถูกลบไปด้วย (FK Cascade) |
| ติด Legal Hold | ✅ ถ้ามีสิทธิ์แชร์ตามปกติ | ✅ ใช้ได้ |

**การปิดเพราะสถานะเอกสารไม่ใช่การยกเลิก** ไม่มีการบันทึกว่าถูกยกเลิก
ลิงก์ยังมีชีวิตอยู่ เพียงแต่ประตูปิดชั่วคราว

**ลิงก์ที่ถูกยกเลิกแล้วไม่กลับมาเอง** ไม่ว่าเอกสารจะกลับมาอยู่ในสภาพใด

Legal Hold คือการ**เก็บรักษา** ไม่ใช่การ**ปกปิด** เอกสารที่ห้ามลบไม่ได้แปลว่าห้ามส่งให้ใคร
ดู [LEGAL_HOLD.md](LEGAL_HOLD.md)

## ที่จัดการ

- **แผงรายละเอียด → การเข้าถึง → การแชร์ภายนอก** - สร้าง คัดลอก ยกเลิก ของเอกสารชิ้นนั้น
- **`/admin/public-shares`** - ภาพรวมทั้งระบบสำหรับผู้ดูแลระบบ

ทั้งสองที่ **ไม่แสดงตัวลิงก์** เพราะเซิร์ฟเวอร์ไม่มีให้แสดง - โทเคนดิบปรากฏครั้งเดียว
ตอนสร้างเท่านั้น ดู [PUBLIC_SHARE_SECURITY.md](PUBLIC_SHARE_SECURITY.md)

## ไม่มีในเฟสนี้

- **อัปโหลดผ่านลิงก์** - พื้นที่ลูกค้าครอบคลุมการรับไฟล์จากภายนอกอยู่แล้ว
- **แก้วันหมดอายุของลิงก์เดิม** - ใช้วิธียกเลิกแล้วสร้างใหม่ ซึ่งมีร่องรอยชัดกว่า
- **เปลี่ยนรหัสผ่านของลิงก์เดิม** - เช่นเดียวกัน
- **ค้นหาในโฟลเดอร์ที่แชร์**
- **QR code**
- **การแจ้งเตือน**
