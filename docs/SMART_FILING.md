# จัดเก็บอัจฉริยะ (F22)

จัดเก็บอัจฉริยะเสนอ "ตำแหน่งจัดเก็บที่น่าจะถูก" ให้เอกสารหนึ่งฉบับ โดยเรียนรู้จากเอกสารที่ถูกจัดเก็บไว้แล้วในระบบ ไม่ใช่จากทะเบียนลูกค้าที่ตั้งไว้ล่วงหน้า ระบบนี้เป็นผู้แนะนำเท่านั้น เอกสารจะเคลื่อนที่ได้ก็ต่อเมื่อผู้ใช้กดยืนยันด้วยตัวเองเท่านั้น

## ขอบเขตที่ AI ทำไม่ได้

- ไม่ย้ายไฟล์เอง ไม่สร้างโฟลเดอร์เอง ไม่เปลี่ยนชื่อ ไม่เปลี่ยนผู้ดูแล ไม่เปลี่ยนสิทธิ์
- การวิเคราะห์เป็นการอ่านอย่างเดียว เขียนเพียงแถวข้อเสนอเท่านั้น
- การย้ายจริงเกิดที่ `acceptSuggestion` ที่เดียว ซึ่งตรวจสิทธิ์ใหม่ทั้งชุดแล้วเรียก `moveResource` ของระบบ ข้อจำกัดของการย้ายด้วยมือทุกข้อจึงมีผลเหมือนกัน รวมถึงบันทึกกิจกรรม `RESOURCE_MOVED`
- การสร้างโฟลเดอร์จากกล่องเลือกปลายทางไม่ย้ายเอกสารตามไปด้วย เป็นสองการกระทำที่ผู้ใช้ยืนยันแยกกัน

## วิธีตัดสิน

สองขั้นตามลำดับ ขั้นแรกหา "ลูกค้า" ขั้นที่สองจึงหาโฟลเดอร์ปลายทางภายในลูกค้ารายนั้น

1. **โฟลเดอร์ลูกค้า** ตรวจจากรูปแบบการตั้งชื่อพี่น้องแบบมีเลขลำดับ (`1.`, `2.`, `3.` …) ตั้งแต่ 3 โฟลเดอร์ขึ้นไป
2. **ตัวระบุของเอกสาร** เลขประจำตัวผู้เสียภาษี 13 หลัก ชื่อบริษัทที่ทำให้เป็นรูปแบบมาตรฐานแล้ว ปีพุทธศักราช รหัสแบบฟอร์ม (ภ.ง.ด. ภ.พ. ฯลฯ) และหมวดเอกสาร
3. **ค้นย้อนกลับ** ถามว่า "เอกสารที่มีตัวระบุเดียวกันนี้ ถูกเก็บไว้ที่โฟลเดอร์ไหนอยู่แล้ว" นับเฉพาะเอกสารที่จัดเก็บแล้วใต้โฟลเดอร์ลูกค้า ไม่นับกล่องขาเข้า
4. **ระดับผลลัพธ์** `CLIENT_ONLY` · `CLIENT_AND_PERIOD` · `FULL_DESTINATION` · `AMBIGUOUS` · `NO_SUGGESTION`

ความมั่นใจของ "ลูกค้า" กับ "ตำแหน่ง" แยกกันเสมอและแสดงแยกกันบนหน้าจอ เพราะกรณีที่พบบ่อยที่สุดคือรู้ลูกค้าแต่ยังไม่รู้โฟลเดอร์ย่อย การยุบเป็นค่าเดียวจะทำให้ผู้ใช้เชื่อผิดในกรณีที่พบบ่อยที่สุด

ผลแบบ `AMBIGUOUS` ไม่มีผู้ชนะโดยปริยาย ผู้ใช้ต้องเลือกเอง และตัวเลือกที่ผ่านการตรวจสิทธิ์แล้วถูกบันทึกไว้กับข้อเสนอ เพื่อให้อ่านกลับมาได้เหมือนตอนวิเคราะห์

## เอกสารที่ยังสกัดข้อความไม่เสร็จ

ไฟล์ที่เพิ่งอัปโหลดยังไม่ผ่านตัวจัดทำดัชนี หลักฐานในจังหวะนั้นมีเพียงชื่อไฟล์ การสรุปว่า "ไม่พบตำแหน่ง" ตอนนั้นเป็นคำตอบที่ระบบยังไม่ได้ตรวจจริง `analyze` จึงตอบ `SMART_FILING_TEXT_NOT_READY` (409) และหน้าจออัปโหลดจะรอเป็นรอบ ๆ แล้วเงียบไปเองถ้ายังไม่พร้อม

สถานะปลายทางอย่าง `NO_TEXT` `UNSUPPORTED` `FAILED` ไม่ถือว่ายังไม่พร้อม ไฟล์ภาพที่สกัดข้อความไม่ได้จึงยังวิเคราะห์จากชื่อไฟล์ได้ตามปกติ

## ความไม่เป็นปัจจุบัน

ข้อเสนอผูกกับ `ResourceVersion` ที่ใช้วิเคราะห์ ถ้าเอกสารมีเวอร์ชันใหม่ ถูกย้าย ถูกลบ หรือปลายทางหายไป/ถูกเพิกถอนสิทธิ์ ข้อเสนอนั้นใช้ยืนยันไม่ได้อีก ต้องวิเคราะห์ใหม่ การเพิกถอนสิทธิ์มีผลที่จังหวะกดยืนยัน ไม่ใช่จังหวะที่สร้างข้อเสนอ

## ตัวช่วยจากโมเดลภาษา (ปิดเป็นค่าเริ่มต้น)

โมเดลได้ทำอย่างเดียวคือ "เรียงลำดับผู้สมัครที่ผ่านการตรวจสิทธิ์มาแล้ว" เพิ่มหรือลบผู้สมัครไม่ได้ และถูกเรียกเฉพาะเมื่อกติกาแน่นอนยังตัดสินไม่ได้ ผู้สมัครที่มีเลขประจำตัวผู้เสียภาษีตรงตัวและไม่กำกวมจะไม่ถูกโมเดลแซงเลย

ผู้สมัครถูกส่งเป็นบล็อกหลักฐาน `E1…En` ของสัญญา F21 เดิม โมเดลจึงเลือกได้เฉพาะรหัสที่เราส่งให้ รหัสที่แต่งขึ้นเองถูกปฏิเสธ ความล้มเหลวทุกชนิด (ปิดอยู่ โมเดลหาย หมดเวลา คิวเต็ม ผลอ่านไม่ได้) ถอยกลับไปใช้ลำดับของกติกาแน่นอนเงียบ ๆ ผู้ใช้ยังได้ข้อเสนอเสมอ

ใช้คิวเดียวกับผู้ช่วยเอกสาร เพราะเครื่องรันโมเดลบน CPU ได้ทีละงาน

## ค่าตั้ง

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
| --- | --- | --- |
| `S2_NAS_SMART_FILING_ENABLED` | `0` | เปิดใช้งานทั้งความสามารถ ปิดอยู่แล้วทุก endpoint ตอบ 503 อย่างชัดเจน ไม่หายไปเงียบ ๆ |
| `S2_NAS_SMART_FILING_LLM_ENABLED` | `0` | เปิดตัวช่วยจัดลำดับจากโมเดลภาษา ต้องมีรันไทม์ของ F21 พร้อมด้วย |

## เวลาที่วัดได้จริง

วัดกับเซิร์ฟเวอร์จริงบนคลังเอกสารจริง (12 ตัวอย่าง)

| รายการ | p50 | p95 |
| --- | --- | --- |
| อัปโหลดเสร็จ | 66 ms | 120 ms |
| ข้อเสนอพร้อมหลังอัปโหลด | 14.8 s | 15.2 s |
| วิเคราะห์เมื่อข้อความพร้อมแล้ว | ~0.2–0.5 s | — |
| วิเคราะห์เมื่อเปิดตัวช่วยโมเดลและต้องเรียกจริง | ~21.6 s | — |

เวลารอข้อเสนอถูกกำหนดโดยรอบการสกัดข้อความ (`S2_NAS_EXTRACT_POLL_SECONDS` ค่าเริ่มต้น 15 วินาที) ไม่ใช่โดยการจัดอันดับ

## API

ทุกเส้นทางอยู่หลัง `requireInternal`

| Method | Path | ผล |
| --- | --- | --- |
| `POST` | `/api/resources/:id/smart-filing/analyze` | วิเคราะห์และเขียนทับข้อเสนอเดิมของผู้ใช้คนนั้นสำหรับเอกสารฉบับนั้น |
| `GET` | `/api/resources/:id/smart-filing/suggestion` | อ่านข้อเสนอปัจจุบันพร้อมสถานะความเป็นปัจจุบัน |
| `POST` | `/api/resources/:id/smart-filing/dismiss` | ปฏิเสธข้อเสนอ เอกสารอยู่ที่เดิม |
| `POST` | `/api/resources/:id/smart-filing/accept` | ยืนยันการย้าย ตรวจสิทธิ์ใหม่แล้วเรียกบริการย้ายเดิม |

บันทึกกิจกรรม `SMART_FILING_ANALYZED` `SMART_FILING_ACCEPTED` `SMART_FILING_DISMISSED` `SMART_FILING_STALE` `SMART_FILING_FAILED` เก็บเฉพาะรหัส ระดับผล ระดับความมั่นใจ ชนิดสัญญาณ และเวลาที่ใช้ ไม่มีเนื้อหาเอกสาร ไม่มี path และไม่มี storage key
