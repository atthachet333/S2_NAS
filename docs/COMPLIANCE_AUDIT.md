# การตรวจสอบเพื่อการกำกับดูแล

เอกสารนี้ตอบคำถามของผู้ตรวจสอบภายในและภายนอก ไม่ใช่คู่มือการใช้งานหน้าจอ
(สำหรับหน้าจอดู [AUDIT_EXPLORER.md](AUDIT_EXPLORER.md))

## บันทึกเพิ่มอย่างเดียว

`activity_logs` เป็น **append-only ในทางปฏิบัติ**

- ไม่มีเส้นทาง API ที่แก้ไขเหตุการณ์
- ไม่มีเส้นทาง API ที่ลบเหตุการณ์
- ไม่มีปุ่มใดในหน้าจอที่ทำสองอย่างนั้นได้
- **F17 ไม่มีการลบบันทึกอัตโนมัติ** ไม่มีนโยบายอายุ ไม่มีงานเก็บกวาด

บันทึกการตรวจสอบที่ลบตัวเองตามเวลา คือบันทึกที่หายไปพอดีตอนที่มีคนเริ่มสืบสวน

การกำหนดอายุของบันทึกเป็นการตัดสินใจเชิงนโยบายที่ต้องมีคนรับผิดชอบระบุอย่างตั้งใจ
ไม่ใช่ค่าเริ่มต้นที่โผล่มาจากซอฟต์แวร์

## ข้อมูลที่ไม่มีวันหลุดออกไป

หน้าจอและไฟล์ส่งออกไม่แสดง:

```
รหัสผ่าน · แฮชรหัสผ่าน · refresh token · access token · id token
Authorization header · Google token · client secret · integration secret
credential hash · storageKey · เส้นทางไฟล์จริงบนดิสก์ · cookie · session
```

### กันสามชั้น

1. **บัญชีอนุญาตรายเหตุการณ์** (`DETAIL_ALLOWLIST`) - แต่ละรหัสเหตุการณ์ระบุไว้ว่าฟิลด์ไหน
   ในกล่อง metadata ที่ออกไปได้ ฟิลด์ที่ไม่อยู่ในบัญชีถูกทิ้งเงียบ ๆ

   **ไม่มีจุดใดที่ส่ง `ActivityLog.metadata` ดิบออกไป** ต่อให้วันนี้ทุกเหตุการณ์สะอาด
   วันหนึ่งจะมีคนเพิ่มฟิลด์ใหม่ที่มีข้อมูลอ่อนไหวโดยไม่ตั้งใจ และไม่มีใครสังเกต
   จนกว่ามันจะไปโผล่ในไฟล์ที่ส่งให้คนนอก

2. **ตัวกรองคำต้องห้าม** (`FORBIDDEN_KEY`) - ชั้นสุดท้าย เผื่อมีคนเผลอเพิ่มชื่อฟิลด์
   อ่อนไหวเข้าไปในบัญชีอนุญาตเอง

3. **ชุดทดสอบบังคับ** - ค้นคำต้องห้ามแบบไม่สนตัวพิมพ์ ทั้งในคำตอบของ API และในไฟล์ CSV จริง

### ข้อมูลอ่อนไหวที่จงใจไม่ใส่บัญชีอนุญาต

- **ข้อความ OCR และข้อความที่แก้แล้ว** - บันทึกเก็บเพียงจำนวนตัวอักษร ไม่เก็บเนื้อหา
- **เหตุผลของ Legal Hold** - เป็นข้อมูลของฝ่ายกฎหมาย อยู่ในตาราง `LegalHold` ซึ่งมีด่านสิทธิ์ของตัวเอง
- **เนื้อหาเอกสาร** - เครื่องมือนี้ไม่ค้นเนื้อในเอกสารเลย

## ค้นอะไรไม่ได้บ้าง

เครื่องมือนี้ **ไม่ค้น**: เนื้อหาเอกสาร ข้อความ OCR ข้อความ OCR ที่แก้แล้ว รหัสผ่าน token

หน้าจอนี้ตอบว่า "ใครทำอะไร" ไม่ใช่ "ในเอกสารเขียนว่าอะไร" - การค้นเนื้อหาอยู่ที่
[CONTENT_SEARCH.md](CONTENT_SEARCH.md) ซึ่งมีด่านสิทธิ์ของมันเอง

การรวมสองอย่างไว้ที่เดียวจะทำให้สิทธิ์ตรวจสอบกลายเป็นสิทธิ์อ่านทุกเอกสารในองค์กรโดยปริยาย

## IP และอุปกรณ์

**IP แสดงเฉพาะผู้ที่มีสิทธิ์ตรวจสอบ** ไม่ปรากฏในไทม์ไลน์ที่ผู้ใช้ทั่วไปเห็น
และไม่ปรากฏในพอร์ทัลลูกค้าเลย

User agent ถูกสรุปเป็นข้อความอ่านง่าย (เช่น "Chrome บน Windows") ด้วยตรรกะในระบบเอง
**ไม่มีการส่งข้อมูลไปยังบริการวิเคราะห์ภายนอก** - การส่ง user agent ของพนักงานออกนอกองค์กร
เพื่อให้ได้ข้อความสวยขึ้น เป็นการแลกที่ไม่คุ้ม

## ใครเข้าถึงได้

| ประเภทบัญชี | เข้าถึงบันทึกการตรวจสอบ |
|---|---|
| INTERNAL ที่มี `system:audit:view` | ได้ |
| INTERNAL อื่น | ไม่ได้ |
| EXTERNAL (ลูกค้า) | **ไม่ได้เลย** |
| SERVICE / Integration | **ไม่ได้เลย** |

การกันเป็นสองชั้น: `requireInternal` ที่เส้นทาง และ `canViewAudit` ที่บริการ

การแก้ตัวกรองใน URL หรือใน body **ไม่ขยายสิทธิ์** ตัวกรองบอกได้แค่ว่า "อยากเห็นน้อยลง"
ไม่มีค่าตัวกรองใดที่ทำให้เห็นมากกว่าที่สิทธิ์อนุญาต

การขอเหตุการณ์ด้วย id ตรง ๆ ก็ผ่านด่านเดียวกัน - ไม่มี IDOR

## ข้อความจากผู้ใช้ไม่ใช่โครงสร้าง

ชื่อไฟล์และชื่อโฟลเดอร์ที่ผู้ใช้ตั้งเองปรากฏอยู่ในบันทึก

- **หน้าจอ**: ทุกค่าถูกแสดงผ่าน children ของ React จึงเป็นข้อความล้วนเสมอ ไม่มี `dangerouslySetInnerHTML`
- **CSV**: ทุกค่าถูกครอบด้วยอัญประกาศ อัญประกาศภายในถูกซ้ำ และค่าที่ขึ้นต้นด้วยอักขระสูตร
  ถูกเติม single quote (ดู [AUDIT_EXPORT.md](AUDIT_EXPORT.md))

มีชุดทดสอบที่ตั้งชื่อโฟลเดอร์เป็น payload แล้วยืนยันว่าจำนวนบรรทัดในไฟล์ยังตรงกับจำนวนแถว
- ชื่อที่มีบรรทัดใหม่จึงไม่สามารถแทรกแถวปลอมเข้าไปในรายงานได้

## เหตุการณ์ในอดีตยังมีความหมาย

ผู้ใช้ในระบบนี้ **ถูกปิดใช้งาน ไม่ถูกลบ** (ดู [USER_MANAGEMENT.md](USER_MANAGEMENT.md))
ผู้ดำเนินการในเหตุการณ์เก่าจึงหาชื่อเจอเสมอ

`userId` ที่ว่างไม่ใช่ข้อมูลขาด แต่หมายถึง **"ระบบ"** - งานตามกำหนดเวลา งานเก็บกวาด
การสำรองอัตโนมัติ ที่ไม่มีมนุษย์คนไหนกดปุ่ม หน้าจอแสดงคำว่า "ระบบ" ไม่ใช่ช่องว่าง

ทรัพยากรที่ถูกลบถาวรแสดงว่า **"ทรัพยากรถูกลบแล้ว"** พร้อมรหัสเดิม
"มีคนดาวน์โหลดอะไรบางอย่างที่ตอนนี้ไม่มีแล้ว" ยังเป็นข้อเท็จจริงที่ผู้ตรวจสอบต้องเห็น

## การกำกับดูแลไม่แก้ประวัติ

การวางหรือปลด Legal Hold **เพิ่ม** เหตุการณ์ ไม่แก้เหตุการณ์เก่า
ประวัติของทรัพยากรก่อนถูกระงับยังอยู่ครบทุกแถว

การลบถาวรที่ถูกปฏิเสธก็ถูกบันทึก:

| รหัส | ความหมาย |
|---|---|
| `PERMANENT_DELETE_BLOCKED_RETENTION` | ติดนโยบายการเก็บรักษา |
| `PERMANENT_DELETE_BLOCKED_HOLD` | ติด Legal Hold |

**ความพยายามลบที่ถูกปฏิเสธคือหลักฐาน** ไม่ใช่เหตุการณ์ที่ไม่เกิดขึ้น - ในการสืบสวน
"มีคนพยายามลบเอกสารนี้สามครั้งหลังได้รับหมายศาล" มีน้ำหนักมากกว่าเอกสารที่นิ่งอยู่เฉย ๆ

ดู [LEGAL_HOLD.md](LEGAL_HOLD.md) และ [DOCUMENT_LIFECYCLE.md](DOCUMENT_LIFECYCLE.md)

## บันทึกต้องรอดจากการกู้คืน

`activity_logs` เป็น **ข้อมูลหลัก** ไม่ใช่ข้อมูลที่คำนวณใหม่ได้

ถ้ามันหายไปตอนกู้คืน องค์กรจะตอบผู้ตรวจสอบไม่ได้ว่าเกิดอะไรขึ้นก่อนหน้านั้น
และไม่มีทางสร้างกลับ เพราะเหตุการณ์ที่ผ่านไปแล้วเกิดขึ้นครั้งเดียว

การซ้อมกู้คืนตรวจสอบว่า **จำนวนเหตุการณ์ไม่ลดลง** และเหตุการณ์ตัวอย่างกลับมาครบทุกฟิลด์
รวมถึง IP, user agent และ metadata ภาษาไทยทีละไบต์

ดู [BACKUP.md](BACKUP.md) และ [RESTORE.md](RESTORE.md)

## รายงานสำเร็จรูป

รายงานทุกชุดคือ **ชุดตัวกรองที่บันทึกไว้** ไม่ใช่ตารางหรือคำสั่งค้นหาชุดที่สอง

รายงานที่ดึงข้อมูลจากที่อื่นจะให้ตัวเลขไม่ตรงกับหน้าจอในวันใดวันหนึ่ง
และไม่มีใครรู้ว่าฝั่งไหนถูก
