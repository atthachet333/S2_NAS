# ชุดค้นหาที่บันทึกไว้

> ตัวกรองทั้งหมดอยู่ใน [ADVANCED_SEARCH.md](ADVANCED_SEARCH.md)

## ทำไมต้องมี

งานเอกสารประจำวันคือการค้นเรื่องเดิมซ้ำ ๆ - "ภงด.53 เดือนนี้", "เอกสารที่ลูกค้าอัปโหลด",
"PDF ที่ตรวจแก้แล้ว" การตั้งตัวกรองห้าอันใหม่ทุกเช้าเป็นงานที่ไม่ควรมีใครต้องทำ

## เก็บเงื่อนไข ไม่ได้เก็บผลลัพธ์

นี่คือจุดสำคัญที่สุดของการออกแบบนี้

ถ้าเก็บ **รายการผลลัพธ์** ไว้ เอกสารที่ถูกถอนสิทธิ์ไปแล้วจะยังโผล่ในชุดที่บันทึกไว้ตลอดไป
กลายเป็นช่องทางเห็นเอกสารที่ไม่ควรเห็นอีกต่อไป

การเก็บ **เงื่อนไข** แล้วค้นใหม่ทุกครั้ง ทำให้ผลลัพธ์ผ่านด่านสิทธิ์ปัจจุบันเสมอ
ชุดค้นหาจึงไม่มีวันกลายเป็นช่องโหว่

## เป็นของส่วนตัว

ชุดค้นหาเป็นของแต่ละคน ไม่แชร์ข้ามผู้ใช้ใน F15

ชื่อที่คนตั้งให้ชุดค้นหามักบอกใบ้เนื้องานที่เขากำลังทำอยู่ เช่น
"ตรวจสอบบัญชีบริษัท ก. ปี 2569" ซึ่งไม่จำเป็นต้องให้คนทั้งองค์กรเห็น

`userId` มาจาก session เสมอ **ไม่มีพารามิเตอร์ให้ระบุเจ้าของในคำขอ** จึงไม่มีทาง
ที่ใครจะขอดูของคนอื่นได้ แม้จะแก้คำขอเอง

การขอชุดของคนอื่นตอบ **404 ไม่ใช่ 403** - 403 จะเป็นการยืนยันว่ารหัสนั้นมีอยู่จริง
ซึ่งเป็นข้อมูลที่ผู้เรียกไม่ควรได้

## การใช้งาน

| การกระทำ | ที่ไหน |
|---|---|
| บันทึกการค้นหาปัจจุบัน | ปุ่ม **บันทึกการค้นหา** ข้างช่องค้นหา |
| เปิดชุดที่บันทึกไว้ | เมนู **การค้นหาที่บันทึกไว้** |
| เปลี่ยนชื่อ / ลบ | ปุ่มในเมนู (เห็นเมื่อชี้ที่รายการ) |

เปิดชุดค้นหาแล้ว **คำค้น ตัวกรอง และการเรียงลำดับ** ถูกเขียนกลับลง URL ครบทั้งชุด
สถานะจึงตรงกับตอนที่บันทึกไว้ทุกฟิลด์

## ตัวกรองถูกตรวจซ้ำตอนอ่าน

ตัวกรองถูกเก็บเป็น JSON ซึ่งฐานข้อมูลไม่ได้บังคับรูปร่างให้

การอ่านออกมาโดยไม่ตรวจซ้ำแปลว่าเชื่อข้อมูลเก่าที่อาจถูกบันทึกไว้ด้วยกติกาคนละรุ่น
ตัวกรองที่ไม่ผ่านการตรวจจึงถูกตัดทิ้ง **ทั้งชุด** ดีกว่าส่งเงื่อนไขครึ่ง ๆ กลาง ๆ
ที่ทำให้ผู้ใช้เห็นผลลัพธ์ผิดโดยไม่รู้ตัว

## ขีดจำกัด

- สูงสุด 100 ชุดต่อคน
- ชื่อซ้ำในชุดของคนเดียวกันไม่ได้ (บังคับที่ฐานข้อมูลด้วย `@@unique([userId, name])`)

## การเก็บรักษา

ชุดค้นหาเป็นข้อมูลที่คนสร้าง ไม่ใช่ข้อมูลที่เครื่องคำนวณใหม่ได้
จึงอยู่ในชุดสำรองเสมอ และการซ้อมกู้คืนตรวจว่ามันกลับมาครบ ดู [RESTORE.md](RESTORE.md)
