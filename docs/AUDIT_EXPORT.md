# การส่งออกบันทึกการตรวจสอบ

`POST /api/audit/export` → ไฟล์ CSV

## เส้นทางเดียวกับหน้าจอ

การส่งออกเรียก `searchAuditEvents` ตัวเดิม ด้วย schema ตัวกรองตัวเดิม และผ่านด่านสิทธิ์ตัวเดิม

**ไม่มีคำสั่งค้นหาชุดที่สองสำหรับการส่งออก**

เส้นทางที่สองคือที่ที่ข้อมูลรั่ว: มีคนแก้ตัวกรองของหน้าจอให้แคบลง แต่ลืมแก้ของการส่งออก
แล้วไฟล์ที่ส่งให้ผู้ตรวจสอบภายนอกมีข้อมูลมากกว่าที่คนกดปุ่มเห็นบนจอ

ผลที่ตามมาคือ **สิ่งที่เห็นบนหน้าจอคือสิ่งที่จะได้ในไฟล์ เสมอ**

## สิทธิ์

ต้องมี `system:audit:export` (หรือเป็น `ADMIN` / `SUPER_ADMIN`)

แยกจาก `system:audit:view` เพราะ "ดูบนจอ" กับ "เอาออกจากระบบเป็นไฟล์ที่ส่งต่อได้"
เป็นความเสี่ยงคนละระดับ - ไฟล์ที่ออกไปแล้วเรียกคืนไม่ได้

องค์กรอาจให้ผู้ตรวจสอบภายในดูได้ แต่ให้เฉพาะผู้ดูแลระดับสูงส่งออกได้

## เพดาน 50,000 แถว

เกินเพดานจะได้ `AUDIT_EXPORT_TOO_LARGE` (HTTP 413) พร้อมข้อความให้แคบช่วงเวลาลง

ไม่เปิดให้ส่งออกไม่จำกัด เพราะคำขอที่กินหน่วยความจำหลายกิกะไบต์จะทำให้เซิร์ฟเวอร์ล่มทั้งเครื่อง
และคนที่กดก็ไม่ได้ไฟล์อยู่ดี บอกให้แคบตัวกรองลงตรงไปตรงมากว่าปล่อยให้ล่มแล้วไม่มีใครรู้ว่าทำไม

ระบบดึงทีละ 500 แถว ไม่ถือทั้งชุดไว้ในหน่วยความจำพร้อมกันตั้งแต่ต้น

## รูปแบบไฟล์

**UTF-8 พร้อม BOM** (`﻿` นำหน้า)

Excel บน Windows เดาการเข้ารหัสจากไบต์แรก ถ้าไม่มี BOM ภาษาไทยทั้งไฟล์จะกลายเป็นอักขระขยะ
และผู้ตรวจสอบจะสรุปว่า "ระบบส่งออกข้อมูลเสีย" ทั้งที่ข้อมูลถูกต้องทุกไบต์

### คอลัมน์ (หัวตารางภาษาไทย)

```
วันที่เวลา · เหตุการณ์ · รหัสเหตุการณ์ · หมวดหมู่ · ผู้ดำเนินการ ·
ประเภทผู้ใช้ · อีเมล · ทรัพยากร · ประเภททรัพยากร · IP · อุปกรณ์ · รายละเอียด
```

มีทั้งชื่อเหตุการณ์ภาษาไทยและรหัสดิบ - ชื่อไทยสำหรับคนอ่าน รหัสดิบสำหรับคนที่ต้องกลับมาค้นต่อในระบบ

### ชื่อไฟล์

เซิร์ฟเวอร์เป็นผู้กำหนด รูปแบบ `s2-nas-audit-YYYY-MM-DD.csv`

**ไม่มีส่วนใดของชื่อไฟล์มาจากผู้ใช้** ชื่อไฟล์ที่ผู้ใช้กำหนดได้คือช่องทาง path traversal
และการปลอมนามสกุลไฟล์

## ป้องกันสูตรใน spreadsheet

ค่าที่ขึ้นต้นด้วย `=` `+` `-` `@` แท็บ หรือ CR ถูกเติม single quote นำหน้า

Excel และ Google Sheets ตีความค่าเหล่านี้เป็น**สูตร** ชื่อไฟล์อย่าง `=cmd|'/c calc'!A1`
ที่ผู้ใช้ตั้งเองได้ จึงกลายเป็นคำสั่งที่รันบนเครื่องของคนที่เปิดไฟล์ตรวจสอบ

เป็นการโจมตีที่เดินผ่านระบบเราไปทั้งเส้นโดยไม่แตะอะไรเลย - ระบบเราแค่บันทึกชื่อไฟล์ตามซื่อ
แล้วส่งต่อให้โปรแกรมที่เชื่อคำสั่ง

single quote นำหน้าเป็นวิธีที่ spreadsheet เข้าใจว่า "นี่คือข้อความ" และยังอ่านค่าเดิมออกครบ

อัญประกาศคู่ภายในค่าถูกซ้ำตามมาตรฐาน CSV และทุกค่าถูกครอบด้วยอัญประกาศ
บรรทัดใหม่ในชื่อไฟล์จึงไม่สามารถแตกเป็นแถวใหม่ได้

มีชุดทดสอบบังคับสำหรับทั้งสองเรื่องนี้

## ไม่มีความลับในไฟล์

ค่าทุกค่าในไฟล์มาจาก `safeDetails` ซึ่งผ่านบัญชีอนุญาตรายเหตุการณ์แล้ว
ดูรายละเอียดที่ [COMPLIANCE_AUDIT.md](COMPLIANCE_AUDIT.md)

มีชุดทดสอบที่ค้นหาคำต้องห้ามแบบไม่สนตัวพิมพ์ในไฟล์ที่ส่งออกจริง

## การส่งออกถูกบันทึก

ทุกครั้งที่ส่งออกสำเร็จ ระบบเขียนเหตุการณ์ `AUDIT_LOG_EXPORTED` พร้อม
จำนวนแถว รูปแบบ ช่วงเวลา และสรุปตัวกรอง

"ใครเอาบันทึกทั้งระบบออกไป เมื่อไร ช่วงไหน" เป็นคำถามที่ผู้ตรวจสอบต้องถามเป็นข้อแรก
ระบบที่ส่งออกได้เงียบ ๆ คือระบบที่ไม่รู้ว่าข้อมูลของตัวเองไปอยู่ที่ไหนบ้าง

**การส่งออกไม่แก้บันทึกเดิม มันเพิ่มบันทึกใหม่**

## ไฟล์ที่ส่งออกไม่ใช่ทรัพยากรของ NAS

ไฟล์ถูกส่งกลับให้ผู้ใช้ดาวน์โหลดทันที **ไม่ถูกเก็บไว้ในระบบไฟล์ ไม่ถูกสร้างเป็นทรัพยากร
และไม่ถูกรวมในชุดสำรอง**

ไฟล์ส่งออกเป็นสำเนาที่คำนวณใหม่ได้เสมอจากข้อมูลต้นทาง การเก็บไว้มีแต่จะสร้าง
สำเนาข้อมูลอ่อนไหวที่ไม่มีใครดูแล ไม่มีวันหมดอายุ และไม่มีใครจำได้ว่ามีอยู่

ข้อมูลที่ต้องรอดคือ `activity_logs` เอง - ดู [BACKUP.md](BACKUP.md)

## ทำไมเป็น POST

การส่งออกมีผลข้างเคียงคือเขียนบันทึก การใช้ `GET` จะทำให้ browser prefetch
หรือการรีเฟรชหน้า สร้างบันทึกการส่งออกปลอมขึ้นมาเอง

บันทึกการตรวจสอบที่มีเหตุการณ์ที่ไม่มีมนุษย์คนไหนตั้งใจทำ คือบันทึกที่เชื่อไม่ได้
